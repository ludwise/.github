# Security Policy

Security reports are welcome and should be handled privately.

## Reporting a vulnerability

Please do **not** open a public GitHub issue for suspected vulnerabilities, exposed secrets, authentication problems, authorization bypasses, data exposure, or other security-sensitive findings.

Until LUDWISE publishes a dedicated security contact or private reporting workflow, please use GitHub's private vulnerability reporting feature when it is available for the affected public repository.

When reporting, include:

- a clear description of the issue;
- affected repository, component, or endpoint;
- reproduction steps or proof of concept;
- expected and observed behavior;
- potential impact;
- any suggested mitigation, if known.

Please avoid accessing, modifying, or retaining data that is not yours, and avoid disruptive testing against production systems.

## Scope

This policy applies to public LUDWISE repositories and publicly reachable LUDWISE services. Private backend and infrastructure repositories are not public disclosure targets.

LUDWISE may update this policy as the project and its security reporting process mature.
